# Native Aquifer port: audited 26.3 semantics

Status: source-audited design notes only. No Native Aquifer execution path is implemented yet. Source of truth is the exact vanilla 26.3 and NeoForge-patched 26.3 artifact generated by scripts/audit_minecraft_26_3_sources.py. This note is not proof of runtime parity.

## Call contract

NoiseBasedAquifer.computeSubstance(x,y,z,density) returns either a BlockState or null. Null means keep the solid terrain result, not air. The side effect shouldScheduleFluidUpdate must be returned alongside each sample.

Early exits, in order:
1. density > 0: clear update flag; return null.
2. Query global FluidPicker at (x,y,z).
3. If y > skipSamplingAboveY: clear flag; return global status at y.
4. If global status at y is lava: clear flag; return lava, or air if debug fluid generation is disabled.
5. Otherwise find four nearest aquifer cell centers and evaluate pressure / flow.

The simple Aquifer implementation is distinct: it returns null for positive density, otherwise global picker result at y, and never schedules an update.

## Cell grid and four-nearest search

- gridX(x)=x >> 4; gridZ(z)=z >> 4. Inverse coordinate=(grid << 4)+offset.
- gridY(y)=floorDiv(y,12); inverse coordinate=grid*12+offset.
- Candidate anchor: gridX(x-5), gridY(y+1), gridZ(z-5).
- Visit candidates in nested order x offset 0..1, y offset -1..1, z offset 0..1: 12 candidates.
- NoiseChunk requests the named positional factory with identifier `aquifer`. RandomState.getOrCreateRandomFactory caches it and derives it as `this.random.fromHashOf("aquifer").forkPositional()`. RandomState initializes `this.random` as `Algorithm.newInstance(worldSeed).forkPositional()`, where Algorithm is LEGACY or XOROSHIRO according to NoiseGeneratorSettings.useLegacyRandomSource.
- Audited XOROSHIRO positional factory: `at(x,y,z)` computes `Mth.getSeed(x,y,z) ^ seedLo` and uses `seedHi` unchanged. It returns a fresh XoroshiroRandomSource.
- Audited XOROSHIRO nextInt(bound): cast nextLong to int, reinterpret unsigned 32-bit, multiply by bound, use the high 32 bits; when the low 32-bit fraction is below bound, reject values below `Integer.remainderUnsigned(~bound + 1, bound)` and draw again.
- Audited Xoroshiro128++ state transition: result=`rotl(s0+s1,17)+s0`; then `s1 ^= s0`; `seedLo=rotl(s0,49)^s1^(s1<<21)`; `seedHi=rotl(s1,28)`. An all-zero seed pair is replaced by the two fixed nonzero constants in the audited source.
- World-seed upgrade for XOROSHIRO: low=`worldSeed ^ 7640891576956012809`; high=low+`-7046029254386353131`; then apply Stafford13 mixing independently to both 64-bit words. The `aquifer` namespace hash is MD5("aquifer"), split into two big-endian 64-bit words, then XORed with the initial positional-factory seed pair before the second positional fork.
- Audited Legacy positional factory: `at(x,y,z)` uses `Mth.getSeed(x,y,z) ^ factorySeed`; `fromHashOf(name)` uses Java String.hashCode(name) XOR factorySeed. LegacyRandomSource seed initialization is `(seed ^ 25214903917) & (2^48-1)`; each bit draw updates `state=(state*25214903917+11) & (2^48-1)` and returns the requested high bits.
- Audited coordinate hash from Mth bytecode: compute `l = (long)(x * 3129871)` with the multiplication overflowing as int32 before widening; then XOR `(long)z * 116129781L` and `(long)y`; finally wrap 64-bit `l = l*l*42317861L + l*11L` and arithmetic-shift right 16.
- Uncached center: positional random factory at integer grid coordinate; draw in exact order nextInt(10) for x, nextInt(9) for y, nextInt(10) for z. Center=(gridX*16+rx, gridY*12+ry, gridZ*16+rz).
- Squared distance uses Java int arithmetic: dx*dx+dy*dy+dz*dz. The insertion logic uses >=, so equal-distance candidates are inserted before earlier equal-distance candidates. Preserve visit order and tie behavior.
- Retain four nearest indices and distances. The fourth status affects the final update-flag fallback even though it is not used in the main pressure barrier terms.
- Location cache and status cache are separate. A location may exist before its FluidStatus is computed.

## Similarity and flow flag

similarity(d1,d2)=1.0-(d2-d1)/25.0. Static threshold is similarity(10*10,12*12) = -0.76.

- If similarity(1,2)<=0: return nearest status at y. If similarity(1,2)>=-0.76, update flag is status1 != status2; otherwise false.
- If similarity(1,2)>0, first handle the special case: nearest fluid is water and global picker at y-1 yields lava at y-1; return nearest fluid and set update flag true.
- Evaluate pressure barriers for pairs (1,2), (1,3), (2,3), using vanilla's ordered similarity multipliers. If density+barrier>0 for any pair, clear update flag and return null.
- Otherwise update flag is true if any holds: statuses 1/2 differ; similarity(2,3)>=-0.76 and statuses 2/3 differ; similarity(1,3)>=-0.76 and statuses 1/3 differ.
- If none holds, fourth-neighbor fallback sets flag only when similarity(1,3)>=-0.76, similarity(1,4)>=-0.76, and status1 differs from status4.
- Debug fluid generation disabled changes returned fluid state to air, but status and update decisions still run.

## Pressure

If the two sampled states at blockY are one lava and one water, pressure is exactly 2.0. Otherwise:
- fluidYDiff=abs(level1-level2); zero difference returns 0.
- averageFluidY=0.5*(level1+level2).
- above=blockY+0.5-averageFluidY.
- base=fluidYDiff/2.0; edge=base-abs(above).
- If above>0: center=edge; gradient=center/1.5 when center>0, else center/2.5.
- Else: center=3.0+edge; gradient=center/3.0 when center>0, else center/10.0.
- If gradient is outside [-2,2], noise contribution is 0. Otherwise sample barrier noise once for this block position and reuse it across pair barriers.
- Pressure=2.0*(noise+gradient).

Use double precision and preserve operation order. Barrier noise is lazy.

## Fluid status generation

For cell center (x,y,z):
- Start with global picker status at center. Set top/bottom to y+12 / y-12.
- Visit these 13 audited surface offsets in order, each multiplied by 16 blocks: (0,0),(-2,-1),(-1,-1),(0,-1),(1,-1),(-3,0),(-2,0),(-1,0),(1,0),(-2,1),(-1,1),(0,1),(1,1).
- Surface coordinates are quart-quantized x/z. Cache key is packed quantized x/z. Surface value=floor(surfaceLevel.sampleValue(quantizedX,0,quantizedZ)).
- Adjusted surface=preliminary surface+8.
- For center offset only, if y-12 > adjusted surface, return global status at cell center.
- If y+12 > adjusted surface, or this is center offset, query global fluid at (sampleX,adjustedSurface,sampleZ). If non-air at adjustedSurface, mark center-under-global-fluid for center offset; if top exceeds adjusted surface, return that global status immediately.
- Track minimum unadjusted preliminary surface.

Surface selection (numeric overloads confirmed against the exact 26.3 bytecode):
- If exclusion sampler's float result, widened to double, is >0.0, partial and full floodedness are -1.
- Else distanceBelowSurface=(lowest preliminary surface+8)-y using Java int arithmetic.
- floodednessFactor uses the double overload Mth.clampedMap(distance,0.0,64.0,1.0,0.0) when center is under global fluid, else 0.0.
- floodedness sampler returns float, widened to double for the double Mth.clamp overload with [-1.0,1.0].
- full threshold uses double Mth.map(factor,1.0,0.0,-0.3,0.8); partial threshold uses double Mth.map(factor,1.0,0.0,-0.8,0.4).
- Fully flooded selects global fluid level; partially flooded selects randomized level; otherwise level is WAY_BELOW_MIN_Y.
- Randomized level: fluid cell=floorDiv(x,16), floorDiv(y,40), floorDiv(z,16); middleY=cellY*40+20. Spread sampler returns float and is multiplied by 10.0F in float precision, then widened to double for Mth.quantize(double,3), whose bytecode is floor(value/3.0)*3 with Java int conversion/multiplication. target=middleY+quantized; result=min(lowest preliminary surface,target).
- Fluid type starts as global type. If level<=-10, not WAY_BELOW_MIN_Y, and global type is not lava, sample lava noise at floorDiv(x,64), floorDiv(y,40), floorDiv(z,64); preserve the exact float-to-double conversion and comparison from the audited implementation.

## Constructor-derived bounds

- minGridX=gridX(volume.minBlockX()-5)
- maxGridX=gridX(volume.maxBlockX()-5)+1
- minGridY=gridY(volume.minBlockY()+1)-1
- maxGridY=gridY(volume.maxBlockY()+1)+1
- minGridZ=gridZ(volume.minBlockZ()-5)
- maxGridZ=gridZ(volume.maxBlockZ()-5)+1
- Flat index=(y*gridSizeZ+z)*gridSizeX+x after subtracting minima.
- Constructor samples maximum preliminary surface over a quart-grid volume, adds 8, then derives skipSamplingAboveY from gridY(maxAdjustedSurface+12)-(-1), converted with fromGridY(...,11)-1.

## Native boundary design constraints

The eventual C++ call should process a full density volume and return parallel outputs: block-state token (including null/keep-terrain and opaque modded-state tokens) and fluid-update boolean. Java should only map state tokens to actual BlockState and commit the chunk, not run per-voxel search or pressure logic.

Per-volume caches: cell center locations; FluidStatus (level+state token); quart-quantized surface levels; lazily sampled barrier noise for current block sample.

Resolved implementation slice (not yet a full Aquifer backend):
- `native/cpp-kernels/src/aquifer_random.cpp` implements Minecraft positional seed derivation, Xoroshiro128++ bounded draws, and LegacyRandomSource bounded draws, preserving Java overflow and rejection behavior.
- Native unit tests cover audited golden vectors for both algorithms.
- GameTest `aquifer_xoroshiro_native_parity` compares Native outputs with the actual 26.3 `XoroshiroRandomSource.forkPositional().at(...)` and `LegacyRandomSource.forkPositional().at(...)`, drawing bounds 10, 9, 10 in vanilla order. The coordinate matrix now includes signed-int extremes. CI/game execution must pass before this is marked runtime-verified.
- Factory seed state is obtained from the actual Minecraft factory through Mixin accessors. Native does not re-derive the world seed or assume a particular random algorithm.

Remaining unresolved before the full Aquifer implementation:
1. Runtime encoding for arbitrary modded FluidPicker states and NeoForge additions to the Aquifer call path.
2. DensitySampler binding and noise sampling transfer for all six Aquifer samplers. Do not make Java-computed per-block values the final architecture.
3. Confirm exact Java floating-point behavior of Mth.quantize, Mth.clampedMap, and noise return types from bytecode before claiming full Aquifer parity.

Do not enable this backend in production until synthetic full-volume parity and real generated-chunk block-hash / fluid-update parity pass.


## Native nearest-four search slice (implemented, runtime integration pending)

The C++ kernel now exposes a batch API, `jpe_runtime_aquifer_nearest_four`, through the Rust runtime ABI. It accepts parallel block-coordinate arrays and emits four center coordinates plus four Java-int-compatible squared distances per sample. Random mode is explicit: 0 selects XOROSHIRO and 1 selects Legacy.

Implementation details:
- The candidate anchor uses wrapped Java int arithmetic for `x-5`, `y+1`, and `z-5`, followed by floor division / arithmetic grid conversion.
- The 12 candidates retain the audited nested order: X 0..1, Y -1..1, Z 0..1.
- Cell-center offsets reuse the already-audited XOROSHIRO or Legacy offset kernels.
- A per-call hash cache stores each grid cell's center once, so overlapping sample neighborhoods do not regenerate the same center.
- Squared-distance subtraction, multiplication, and addition preserve Java int32 wrap semantics.
- Equal distances insert the later candidate before earlier candidates, matching the audited vanilla insertion behavior.
- Results are sample-major, with four consecutive neighbor entries per input sample. The maximum batch is 1,048,576 samples.

A Rust unit test independently enumerates the 12 candidates and compares the four returned centers and distances for both RNG modes, including negative coordinates and signed-int extremes.

The C++/Rust batch kernel now has an optional Java FFM binding in `NativeRuntime.aquiferNearestFour(...)`. It accepts three equal-length coordinate arrays and performs one downcall for the whole batch; output arrays are sample-major with four consecutive neighbors per input. The bridge validates mode, lengths, and the 1,048,576-sample ceiling, and uses a confined arena for the batch transfer. This is still not a Minecraft execution path: no Aquifer mixin currently captures production coordinates or invokes the batch bridge. FluidStatus caching, pressure, surface/fluid sampling, block-state mapping, and real generated-chunk parity remain outstanding. Do not treat the bridge as a production backend or assume it is faster until full-volume measurements include array preparation, FFM copies, and the native call. Do not enable it in production until those layers and full-volume parity are complete.
